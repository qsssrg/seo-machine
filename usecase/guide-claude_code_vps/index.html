Claude Codeを24時間フル稼働！VPSで自動コーディング環境を維持する方法

最初に結論を書いておく

Claude CodeはGPU不要。CPUとメモリだけで動く。これだけは最初に言わせてほしい。

なぜこんな出だしにするかというと、「Claude Code用VPS」という名目でGPUプランを勧めてくる記事がちょくちょくある。はっきり書いておくと、あれはアフィリエイト報酬が高いプランに誘導したいだけで、技術的な根拠は一切ない。Claude CodeはAPI経由でAnthropicのサーバーに処理を投げる仕組みなので、VPS側にGPUは関係ない。GPU搭載プランに月数万円払っても、Claude Codeの動作はCPU+メモリだけのプランと変わらない。

自分が出した結論はこれ：

  • 月76時間以上使う人 → XServer VPS（830円固定。毎月いくらか計算しなくていいのが精神的にラク）
  • 月76時間未満・不定期の人 → KAGOYA（使った分だけ払う時間課金。固定料金の無駄がない）
  • まず試したい人 → KAGOYAの14日無料トライアル（週末が2回入る。平日は仕事で触れなくても、2回の週末で確認には十分）

根拠は後半で具体的な金額を出しながら書く。まずはVPSが必要な理由から。

なぜローカルPCじゃダメなのか

正直に言うと、自分も最初は「PCつけっぱなしでいいか」と思ってた。でもこれ、やってみるとじわじわ精神的にキツくなる。

  • 帰宅したら「途中で止まってた」がある
  • PCを閉じるたびに「あ、Claudeも止まる」と気になる
  • 何かトラブルがあったらリモートデスクトップで入らないといけないから、結局「手放し」に全然ならない

「手放しにならない」のが一番しんどい。せっかくAIに作業を任せてるのに、自分がPCを管理し続けないといけない本末転倒な状態になる。これが続くと「なんでAI使ってるんだっけ」ってなる。

VPSにしてしまえば、気にしなくていい。SSHで繋いでtmuxを立ち上げたら、あとはPCの電源を切っても問題なく動き続ける。これが精神的にかなりラクで、一度これに慣れるとローカルで動かしてたのが馬鹿らしくなる。自分はここに気づくのに少し時間かかったけど、気づいてからは迷わなかった。

必要なVPSスペック（GPU推しには乗らなくていい）

もう一回書く。Claude CodeにGPUは不要。

API経由でAnthropicのクラウドに処理が飛ぶので、VPS側でやることは「Claude Codeのプロセスを維持する」だけ。それにGPUは要らない。Claude Code用途で「GPUプランがおすすめ」と書いてある記事を見たら、アフィリエイト報酬目的の誘導を疑っていい。技術的な根拠が何も書いてないなら、ほぼそれだと思っていい。自分の場合、そういう記事を見たときに「なんでGPUが要るんだろう」と考えてみたけど、どう考えても理由が出てこなかった。出てこないのが答え。

4GBメモリのプランで月1,000円台から始められる。それで十分動く。

XServer VPS →

XServer VPSは2GBプランから用意があって、Claude Code単体の常駐なら月額830円台から始められる。国内データセンターなのでSSHのレスポンスが速くて、操作感のストレスがない。固定料金なので「今月いくらかかったっけ」を考えなくていいのは地味にありがたい。ただ、「月に数時間しか使わないかも」という人には後述の時間課金のほうが合ってる。自分の場合、毎月計算するのが面倒なタイプなので固定料金の安心感は結構でかかった。

VPSセットアップ手順

ステップ1：基本環境の構築

# Ubuntu 24.04 LTS を想定
sudo apt update && sudo apt upgrade -y
sudo apt install -y git curl tmux screen unzip build-essential

# Node.jsのインストール（nvmで管理）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install --lts
nvm use --lts
node -v  # v22.x以上を確認

tmuxは最初から入れておく。これがないと24時間常駐の意味がなくなる。「後でいいか」と後回しにしがちだけど、先に入れておくほうが絶対にいい。ここだけは面倒くさがらないでほしい。

ステップ2：Claude Codeのインストール

npm install -g @anthropic-ai/claude-code

# インストール確認
claude --version

ステップ3：APIキーの設定

# Anthropic APIキーを環境変数に設定
echo 'export ANTHROPIC_API_KEY="sk-ant-api03-YOUR-KEY-HERE"' >> ~/.bashrc
source ~/.bashrc

# 動作確認
claude --help

APIキーはAnthropicのコンソール（console.anthropic.com）から取得できる。必ず使用上限（Usage Limit）を設定しておくこと。これは本当に大事。VPSで24時間動かすと、cronや自動化の設定ミスで意図せず大量リクエストが飛ぶことがある。上限なしで放置すると、朝起きたら数万円のAPIコストが発生していた、という話になりかねない。自分はここを軽く考えてたタイプだけど、一度ヒヤっとしてから必ず最初に設定するようにした。

ステップ4：tmuxで24時間常駐させる

ここが本題。tmuxはセッションを維持し続けるターミナルマルチプレクサで、SSH接続が切れてもセッションがサーバー上に生き残る。これを知ってから開発のやり方がかなり変わった。「PCを閉じる＝作業中断」から解放されるのが実感として大きい。

# 新しいtmuxセッションを作成
tmux new-session -d -s claude-work

# セッション内でプロジェクトを開いてClaude Codeを起動
tmux send-keys -t claude-work 'cd ~/my-project && claude' Enter

# SSH切断後もセッションが生きている
# 再接続時
tmux attach -t claude-work

一度これに慣れると、ローカルで動かしてた頃には戻れない。これは大げさじゃなくてわりと本当の話。

ステップ5：複数プロジェクトを並行管理

# セッションごとにプロジェクトを分離
tmux new-session -d -s project-a 'cd ~/project-a && claude'
tmux new-session -d -s project-b 'cd ~/project-b && claude'

# セッション一覧確認
tmux list-sessions

# 切り替え
tmux attach -t project-a
tmux switch -t project-b  # tmux内からの切り替え

自動化ワークフローの設定

長時間タスクをバックグラウンドで実行

Claude Codeの--printフラグを使うと、非対話型で結果を出力できる。「Claudeに任せて寝る」ができるのはこれのおかげ。自分はこれが使いたくてVPSに移行したと言っても過言じゃない。

# 特定のタスクをバックグラウンド実行してログに残す
nohup claude --print "このディレクトリのREADME.mdを更新して、新機能を追加してください" \
  >> ~/logs/claude-tasks.log 2>&1 &

echo "バックグラウンドPID: $!"

Cronで定期タスクを自動実行

# crontabを編集
crontab -e

# 毎朝6時にテストを実行してSlackに通知
0 6 * * * cd ~/my-project && claude --print "テストを実行して失敗しているものがあれば修正してください" >> ~/logs/daily-test.log 2>&1

cron設定のミスはAPI料金に直結する。最初は必ず手動で動作確認してから自動化に移行する。「動いてるかな？」が不安な間は自動化しない。正直、ここで焦って自動化しようとするのがいちばんよくないパターン。設定ミスのまま放置は事故のもとなので、慎重にやっていい場面。

GitHub Actionsと連携

# .github/workflows/claude-review.yml
name: Claude Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'

      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: Run Claude Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          claude --print "このPRの変更をレビューして、問題点や改善点をコメントしてください" \
            > review-output.txt
          cat review-output.txt

コスト管理のポイント（ここが一番重要かもしれない）

VPSのコストとAPI料金、両方かかるので整理しておく。「思ってたより高かった」は防げる話だから、ちゃんと計算しておくほうがいい。自分も最初は雰囲気で選んでたけど、ちゃんと計算したら判断がシンプルになった。

VPS月額の目安：

  • XServer VPS 2GBプラン：830円〜（固定）
  • KAGOYA VPS：約0.5〜1円/時間（時間課金、スペックによる）

KAGOYAの時間課金を実際に計算してみる：

仮に1時間あたり11円のプランで使った場合：

  • 1日1時間使用 × 30日 = 30時間 → 330円/月（これはかなり安い）
  • 1日5時間使用 × 30日 = 150時間 → 1,650円/月
  • 24時間フル稼働 × 30日 = 720時間 → 7,920円/月（これは高すぎる。フル稼働ならXServer一択）

XServer vs KAGOYAの損益分岐点：

XServerの830円固定プランとKAGOYAの時間課金（1時間11円で計算）を比べると：

830円 ÷ 11円/時間 ≒ 75.5時間

つまり月76時間を超えて使うならXServerが安くなる。月76時間は1日あたり約2.5時間。毎日コードを書く人ならすぐ超える数字。逆に、週末だけとか不定期な人は時間課金のKAGOYAのほうが無駄がない。

本音を言えば、「毎月いくらかな」と計算したくない人には830円固定のXServerのほうが精神的にラクだと思う。時間課金はお得な場面もあるけど、「今月どれくらい使ったっけ」が気になり始めると地味にストレスになる。そのストレス込みで考えると、ある程度使うなら固定の方が総合的にはいいと感じてる。
