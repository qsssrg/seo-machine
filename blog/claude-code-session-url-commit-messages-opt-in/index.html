Claude Codeがコミット履歴にセッションURLを自動追記——「汚染」と呼ぶ前に考えたいこと

「git historyが汚染された（polluted）」——そう表現したのは、GitHub issue #66504を起票した開発者だ。Anthropicが提供するAI開発支援ツール「Claude Code」が、コミットメッセージやプルリクエストの説明文に自動でセッションURLを追記する仕様が話題を呼び、Hacker Newsでも多くのコメントが集まった。

でも少し立ち止まって考えてほしい。本当に問題なのは「URLが付く」こと自体なのか？

何が起きているのか

Claude Codeを使ってコードを書き、コミットやプルリクエスト（変更提案）を作ると、その説明文の末尾に https://claude.ai/code/session_... という形式のURLが自動で追記される。このURLは、その作業セッションへのリンクだ。

問題として挙げられているのは主に3点だ。

  1. 知らないうちに追記されている — 初回利用時の説明もなく、設定の選択肢も提示されない
  2. チームや外部の目に触れる — オープンソースプロジェクトや職場のリポジトリでは、チームメンバーや外部のコントリビューターも目にする
  3. 後から消しにくい — gitの履歴はいちど書き込まれると書き換えが難しく、「汚染」という言葉が使われた

回避策は一応ある。.claude/settings.json（Claude Codeの設定ファイル）の attribution.commit の値を空文字列にすると、追記が止まる。また、gitの「コミット直前に自動で走るスクリプト」（commit-msgフック）を使って削除する方法もある。ただし後者はリモート環境やクラウド環境では動作しないケースがある、とissueは指摘している。

問題は、どちらの回避策も「気づいた人だけが使える」点にある。

「URLが付く」ことは本当に問題なのか

ここで逆の視点から考えてみたい。

Claude Codeはすでに Co-Authored-By: Claude というコミットのトレーラー（付記情報）を付けている。「このコードはAIと一緒に書きました」という事実の開示だ。これについて大きな反発はあまり起きていない。

そう考えると、セッションURLが付くことの実害は何だろうか。issueのコメントを読み込むと、「プロフェッショナルらしくない見た目になる」「チームに内緒でAIを使っていたことがバレる」といった背景が見え隠れする。

つまり「URLが余計だ」という不満の裏には、「AIツールを使っていたことを開示したくない」という心理が含まれているのかもしれない。それはURLの問題ではなく、AI利用の透明性をめぐる職場やコミュニティの規範の問題だ。

もちろん、そうした規範はまだ形成途上であり、「開示するかどうかは個人が決めるべきだ」という立場も十分に正当だ。

それでも「オプトイン」は正しい要求だ

そうはいっても、issue #66504の要求は正当だと思う。

技術的な不具合というより、同意（コンセント）の設計問題だ。「後から知る」設計はユーザーに選択肢を与えていない。「付けたい人は付けられる」ではなく「気づいた人だけ外せる」は、UX（ユーザー体験）として逆向きだ。

issueが提案する理想の形は明快だ。「このClaude Codeセッションへのリンクをコミットメッセージに含めますか？」という、一度だけのプロンプト（確認画面）。それだけでほとんどの摩擦は消える。

Alternative（代替案）として、「オプトインではなくオプトアウトのままでいいが、初回コミット時に『追記しない』ボタンを出す」という提案も寄せられており、段階的な改善案が複数提示されている。

なお、issueは2026年6月9日に起票されており、現時点でAnthropicが公式に方針変更を発表したかどうかは元の情報からは確認できない。気になる方はGitHub issue #66504の最新状況を直接確認することをお勧めする。

開発ツールの「自己宣伝」問題

もう少し広い文脈で見ると、これはAI開発ツール全般に共通する課題でもある。

ツールが「自分が使われた」ことを出力物に刻み込む行為は、ユーザーではなくツール側の利益になる可能性がある。ブランド露出や、サービス認知の拡大につながる。ユーザーがそれを望む場合は問題ない。だが、デフォルトでオンにしておくのは話が別だ。

「気づかないうちに宣伝に加担させられていた」という感覚は、製品への信頼を損なう。Claude CodeはGitHubで143,000以上のスター（支持の印）を集める人気ツールだけに、こうした設計の選択が注目を集めるのは当然だろう。

まとめ：URLの問題ではなく、同意設計の問題

Claude Codeのセッション追記問題は、「URLが邪魔だ」という表面的な不満の奥に、AIツール利用の透明性と同意設計という本質的なテーマを持っている。

「使ったことを開示すべきか」という議論は今後も続くだろうが、それ以前に「ユーザーが選べること」が大前提だ。AIツールが日常的な開発に組み込まれていくほど、こうした設計の細部が積み重なって、開発者とツールの信頼関係を左右する。

自分のコミット履歴やプルリクエストに何が書き込まれているか、一度確認してみてもいいかもしれない。
