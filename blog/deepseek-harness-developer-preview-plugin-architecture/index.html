DeepSeek Harness developer preview——「すべてがプラグイン」というAIエージェント設計思想

DeepSeekが「DeepSeek Harness」のデベロッパープレビューを公開した。AIエージェント（自律的にタスクをこなすAIプログラム）を構築するための基盤ソフトウェアで、ソースコードも公開されている。npx @deepseek-ai/dsh web の1コマンドで試せる手軽さと、「すべてがプラグイン（Everything is a plugin）」という設計哲学が、Hacker Newsで多くの注目を集めた。

モデルは「魂」、ハーネスは「手足」

DeepSeek Harnessのドキュメントには、こんなひと言がある。

モデルはエージェントの魂である。ハーネスはエージェントが環境を理解し、ツールを使い、現実世界で動き続けるための仕組みだ。

この比喩はなかなか的を射ている。どれほど優秀なAIモデルであっても、それだけでは「賢い頭脳が宙に浮いている」状態に過ぎない。ファイルを読み書きする、ウェブを検索する、別のプログラムを呼び出す、作業の進捗を記録する——そうした「手足」の部分を整えてはじめて、モデルは実際の仕事をこなせるようになる。DeepSeek Harnessが担うのはまさにその「手足」の設計だ。

「すべてがプラグイン」とはどういうことか

DeepSeek Harnessの中核は「Cordis」と呼ばれるプラグイン管理の仕組みだ。このCordisカーネルがプラグインの追加・削除・依存関係を管理し、エージェントのあらゆる能力——モデルの選択、ツール、スキル、セッション管理、サンドボックス（隔離された実行環境）、ストレージ、ループ制御、スケジューリング、さらにはUIにいたるまで——をプラグインとして提供する。

「すべてがプラグイン」という設計の利点は、DeepSeek Harnessのソースコードに手を入れることなく、設定ファイルだけで任意の能力を差し替えられる点にある。

たとえばレゴブロックで建物を作るとき、柱を別の素材に変えたくなったら、その柱だけ抜いて挿し直せばいい。建物全体を壊す必要はない。DeepSeek Harnessの設計はそれに近い。使うモデルを変えたい、別のツールを足したい、UIを差し替えたい——そうした変更が、システム全体に影響を与えずに行える。

4つの実行モード

DeepSeek Harnessには現在4つの実行モードがある。

**Standard mode（標準モード）**はフルセットのツールを備えたコーディングエージェントで、ファイル編集、シェル操作、ファイル検索、ウェブ検索、計画立案、サブエージェント（タスクを分担する子エージェント）の起動などを扱う。

**Code mode（コードモード）**は標準モードの能力をベースに、モデルが生成したTypeScriptコードを通じて複数のツール操作をひとまとめに実行できる仕組みを加えたもの。複雑な手順を1本のプログラムとして記述させることで、精度と再現性を高める狙いがある。

**Minimal mode（最小モード）**はシェルとファイルエディタだけを残したシンプルな構成で、モデル自体の性能を公平に評価するベンチマーク（性能測定）用に設計されている。余計な道具を持たせないことで、「このモデルはそもそも何ができるか」を純粋に測れる。

**Creator mode（クリエイターモード）**は開発者向けで、実行中のプラグインをメモリ上で試したり、カスタムの動作設定（プリセット）を作ったりできる。エージェントを使うのではなく、エージェントそのものを設計したい人のためのモードだ。

「すべての実行は追跡可能」——トレーサビリティへのこだわり

DeepSeek Harnessが「Every run is traceable（すべての実行は追跡可能）」というもうひとつの設計原則を掲げているのが興味深い。

エージェントが動くとき、モデルが見たすべての情報——システムプロンプト（エージェントへの基本指示）、推論の過程、ツールの呼び出しと結果、サブエージェントのスケジューリング、あらゆるコンテキストの注入——が「追記専用のセッションログ」として記録される。一度書かれたものは書き換えられない形式のため、後からでも何が起きたかを正確に追える。

「Trajectory view（軌跡ビュー）」ではこれらの記録を発生源ごとに検査でき、さらに実行の再開（Resume）、分岐（Fork）、検索（Search）、再現（Replay）がすべて同一のイベントストリーム上で動く。

このトレーサビリティへのこだわりは、AIエージェントの運用における本質的な課題に向き合っている。エージェントが誤った判断をしたとき、あるいは予期しない挙動をしたとき、「なぜそうなったのか」を後から追えなければ改善のしようがない。ブラックボックスでは困る、という開発者の切実な声に応えた設計だと言える。

オープンソース基盤としての意義

DeepSeek Harnessはまだデベロッパープレビュー段階にあり、コアのプラグインとAPIは今後も変化していく予定だと明記されている。コミュニティプラグインの仕組みも用意されており、開発者が独自に拡張を作って共有できる生態系を育てようとしている。

「再利用可能でコンポーザブル（組み合わせ自在）なオープンソース基盤を使って、世界中の開発者とともにインテリジェンスの限界を探求していきたい」という言葉が、このプロジェクトの姿勢をよく表している。

モデルの性能競争が一段落しつつある中で、「エージェントを現実世界で確実に動かすための基盤」に焦点が当たり始めている。DeepSeek Harnessのデベロッパープレビューは、その流れの中に位置する一手と言えるだろう。
