自分の「分身AI」がチームを動かす──Munder Difflinが提案するAIクローンオフィス

深夜3時。チームのSlackに「この請求サービスの仕様、どうなってる？」と質問が飛んできた。でも自分はとっくに眠っている。翌朝気づいて返信するころには、相手の作業が4時間止まっていた──そんな経験、一度はないだろうか。

「自分のクローンが答えてくれたらいいのに」。半分冗談のように思い続けていたその発想を、本気でシステム化しようとしているプロジェクトが注目を集めている。その名も Munder Difflin（マンダー・ディフリン）。米国の人気コメディドラマ「ザ・オフィス」に登場する架空の会社名から取ったこのツールは、「あなたのクローンがオフィスを動かす」というコンセプトのAIエージェント基盤だ。

「クローン」とはどういう意味か

Munder Difflinが言う"クローン"は、あなたの作業の癖・使っているツール・蓄積した知識を学習したAIエージェントのこと。

仕組みは3ステップで説明されている。

  1. ハーネスをインストールする ── 既存のエージェントCLI（コマンドラインインターフェース、キーボードで操作する対話型ツール）をラップする1回きりのセットアップ。自分のコード・APIキー・サブスクリプションはすべて自分のマシン上にとどまる。
  2. クローンが"あなた"になる ── ワークフロー、ツール、知識をキャプチャする。一度学んだ記憶は「MemPalace」と呼ばれる仕組みで管理され、次に立ち上げるクローンにも共有される。2体目以降は最初から"あなたのやり方"を知った状態で起動する。
  3. クローンたちがオフィスを動かす ── クローン同士はメッセージを送り合い、仕事を引き継ぎ、詰まったら別のクローンに問い合わせる。すべて自分のマシン上で完結する。

デモとして公開されているのは「JimのクローンとPamのクローン」のやり取りだ。午前3時、請求関連のデザイントークン（UIの色・サイズなどの設計変数）が必要になったJimのクローンがPamのクローンに問い合わせる。Pamのクローンはファイルを即座に返信し、Jimのクローンは朝までにPR #147を開いてテストをグリーンにする──という流れが示されている。人間は全員眠っている時間帯の話だ。

司令塔が指示を読んで振り分ける

内部的には「オーケストレーター（orchestrator）」と呼ばれる司令塔が、Slackなどから届いたトリガーを読み取り、計画を立て、適切なエージェントに仕事をルーティングする。

開発タスクであれば Claude Code でビルドし、Codex でレビューし、Claude Code でgit操作まで行う、という具合にエージェントを組み合わせる設計になっている。各エージェントは独立したワークツリー（作業領域）の中で動くため、互いの作業が干渉しない。

クローンの用途はエンジニアだけに限らないとしている点も特徴的だ。

  • デザイナーのクローン ── デザインシステムに照らした画面監査、アセット書き出し、仕様書の下書き
  • プロダクトマネージャーのクローン ── 仕様書作成、課題のトリアージ（優先度仕分け）、ボードとドキュメントの同期
  • 営業・GTMのクローン ── アウトリーチ文の下書き、CRM管理、フォローアップ
  • その他の役割 ── 報告書、スプレッドシート、スケジュール調整など、スクリプト化できる作業全般

「コマンドラインから操作できることなら何でもできる」というのが設計思想で、コンピューター上でできることはおおむねカバーできるとしている。

セキュリティの設計思想──「約束ではなくアーキテクチャで守る」

AIがチームのコードや会話の文脈を扱う以上、「情報がどこに行くのか」は最大の懸念になる。Munder Difflinが打ち出しているのは「約束ではなく、アーキテクチャそのものでプライバシーを担保する」という考え方だ。

  • ローカルファースト ── 各クローンはそのメンバーのラップトップ上で動く。コード・APIキー・個人的な文脈は機械の外に出ない。通信はすべて 127.0.0.1（自分のPC内のアドレス）で完結する。
  • エンドツーエンド暗号化（E2E） ── クローン間のメッセージは送信側のノードで暗号化され、受信側のノードでのみ復号される。暗号方式はX25519（鍵交換）とAES-256-GCM（データ暗号化）の組み合わせ。開発元を含む第三者は内容を読めない。
  • 組織共有と個人データの分離 ── チーム全体で共有する知識ベースと、個人の記憶は明確に区別される。「共有」と「個人」が混在してサイレントに情報が漏れる設計にはなっていないとしている。
  • オープンソース（MITライセンス） ── ノード、プロトコル、暗号化のコードはすべてGitHubで公開されており、誰でも自分でコードを読んで検証できる。

ネットワーク上を流れるメッセージのデモでは、暗号化された文字列だけが表示され、内容は一切読み取れない形になっている。

ラップトップを閉じてもクローンを動かし続けるオプション

基本的な構成はラップトップ上でのローカル動作だが、「Cloud + Network」ライセンスを使うと、各クローンを専用のサンドボックスVM（仮想マシン）上で24時間動かし続けられる。ラップトップを閉じてもクローンは起動し続け、ターミナルを開いたまま作業を続ける。ローカル動作へのスイッチバックもいつでも可能だという。

アプリ本体はオープンソースで、ラップトップ上での動作は無料。その上に「クローンの動作場所の提供（Cloud）」と「ネットワーク層の提供（Network）」という2つのオプションサービスを販売するビジネスモデルになっている。

現時点での見方と注意点

Hacker Newsでも話題を集めているこのプロジェクトだが、現状はまだ初期段階と見るのが妥当だ。公開されているのは主にコンセプトとデモであり、実際に組織規模でどこまで安定して動作するかは今後の検証が必要になる。

AIエージェント同士が連携して複雑な仕事を分担させる「マルチエージェント」と呼ばれるアプローチは、業界全体で研究・実用化が進んでいる。Munder Difflinはその発想を「チームメンバーごとのクローン」という具体的な形で表現しようとしている点が新鮮だ。

ただ、人間が寝ている間も止まらないオフィスというビジョンを現実にするには、クローンが誤った判断をした場合の影響範囲の管理や、いつ人間に判断を委ねるか（エスカレーション）のタイミング設計が重要になる。ツール自体は「人間が本当に必要な判断だけを引き上げる」を明示的な設計目標に掲げており、そのバランスがどこまで現実的に実現できるか、今後の進捗が注目される。
